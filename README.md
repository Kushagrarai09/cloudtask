# ☁️ CloudTask – Serverless Job Processing Platform

CloudTask is a serverless job processing platform built using **TypeScript and AWS**.

It allows applications to submit tasks that take time to complete, process those tasks in the background, and track their progress without making users wait.

For example, imagine uploading 1,000 images to an application. Instead of processing all images while the user waits, CloudTask places the work in a queue and processes it using background workers.

The application can immediately return a job ID, which users can use to check the processing status.

---

## 🚀 1. What Does CloudTask Do?

CloudTask helps applications manage background tasks efficiently.

Its main capabilities include:

- **Job Submission:** Accept tasks through REST API endpoints.
- **Background Processing:** Process tasks asynchronously using AWS Lambda.
- **Queue Management:** Store pending tasks in Amazon SQS.
- **Job Tracking:** Monitor whether a task is queued, processing, completed, or failed.
- **Result Storage:** Save processed results in Amazon S3.
- **Duplicate Prevention:** Use idempotency keys to avoid creating duplicate jobs from repeated requests.
- **Scheduled Jobs:** Support scheduled task submission using Amazon EventBridge.
- **Workflow Orchestration:** Use AWS Step Functions to coordinate task execution.
- **Monitoring:** Track worker errors using Amazon CloudWatch.

## 🧠 2. Understanding How CloudTask Works

Think of CloudTask as a digital task manager.

When someone submits a task, the platform receives it, stores its details, adds it to a queue, and assigns it to a background worker.

### Step-by-step workflow

1. **User submits a task:** The application sends a request to CloudTask.
2. **API Gateway receives the request:** It forwards the request to an AWS Lambda function.
3. **Job information is stored:** DynamoDB saves the task details and its initial status.
4. **Task enters the queue:** Amazon SQS stores the task until a worker can process it.
5. **Worker processes the task:** Another Lambda function receives the queued task and executes it.
6. **Result is stored:** Amazon S3 stores the output generated by the worker.
7. **Status gets updated:** DynamoDB records whether the task completed or failed.
8. **User checks the result:** The application can retrieve the latest task status through the API.

### Architecture overview

```text
             USER / CLIENT
                  |
                  v
              API GATEWAY
                  |
                  v
             AWS LAMBDA
             (API Handler)
                  |
             +----+-----+
             |          |
             v          v
          DynamoDB   Amazon SQS
          (Job Data) (Task Queue)
                        |
                        v
                    AWS LAMBDA
                   (Background
                      Worker)
                        |
                        v
                     Amazon S3
                   (Task Results)
                        |
                        v
                     DynamoDB
                  (Updated Status)
```

## ⚙️ 5. Installation and Setup

### Prerequisites

Make sure you have:

- Node.js 22 or newer
- npm
- Git
- AWS account
- AWS CLI
- AWS credentials configured
- AWS CDK

### Step 1: Clone the repository

```bash
git clone https://github.com/Kushagrarai09/cloudtask.git
cd cloudtask
```

### Step 2: Install dependencies

```bash
npm install
```

### Step 3: Configure AWS credentials

```bash
aws configure
```

Provide your AWS Access Key, Secret Access Key and default region.

For this project, the example region is:

```text
ap-south-1
```

### Step 4: Configure environment variables

Create your local `.env` file using `.env.example` as a reference.

The deployed Lambda functions receive their resource configuration through CDK.

### Step 5: Run tests

```bash
npm test
```

### Step 6: Check TypeScript

```bash
npm run typecheck
```

### Step 7: Build the project

```bash
npm run build
```

## ☁️ 6. Deploying CloudTask to AWS

CloudTask uses AWS CDK to create the required cloud infrastructure.

First, bootstrap your AWS account:

```bash
npx cdk bootstrap
```

Set your deployment environment:

```bash
export AWS_REGION=ap-south-1
export STAGE=dev
```

For Windows PowerShell:

```powershell
$env:AWS_REGION="ap-south-1"
$env:STAGE="dev"
```

Generate the infrastructure template:

```bash
npm run synth
```

Deploy the infrastructure:

```bash
npm run deploy
```

After deployment, CDK provides important outputs such as:

- API URL
- SQS Queue URL
- S3 Bucket Name
- Step Functions Workflow ARN

**Important:** AWS deployment can incur charges. Review resources and pricing before deploying.

To remove a non-production deployment:

```bash
npm run destroy
```

## 🔌 7. API Documentation

CloudTask exposes REST API endpoints for managing jobs.

### 1. Create a Job

**Endpoint**

```http
POST /jobs
```

**Request Body**

```json
{
  "type": "REPORT_GENERATION",
  "payload": {
    "report": "monthly",
    "format": "pdf"
  }
}
```

**Response**

```json
{
  "jobId": "generated-job-id",
  "status": "QUEUED"
}
```

The API returns a job ID so that the client can track the task.

### 2. Get Job Status

**Endpoint**

```http
GET /jobs/{jobId}
```

Returns the current information about a particular job.

### 3. List Jobs

**Endpoint**

```http
GET /jobs?limit=20
```

Returns a list of submitted jobs.

### 4. Generate Upload URL

**Endpoint**

```http
POST /uploads/presign
```

**Request Body**

```json
{
  "fileName": "report.csv",
  "contentType": "text/csv"
}
```

Returns a temporary S3 presigned URL that can be used to upload a file.

## 🔐 10. Reliability and Security

CloudTask demonstrates several important distributed-system concepts:

- **Asynchronous Processing:** Users do not have to wait for lengthy tasks.
- **Idempotency:** Repeated requests can reuse an existing job ID.
- **Dead Letter Queue:** Failed messages can be isolated after repeated delivery attempts.
- **Automatic Scaling:** Lambda can scale based on incoming workloads.
- **Persistent Storage:** DynamoDB and S3 preserve task information and outputs.
- **Monitoring:** CloudWatch helps identify worker failures.

### Production improvements

Before using this platform in a production environment, implement:

1. Authentication and authorization using AWS Cognito or JWT.
2. Tenant-level access control.
3. Transactional outbox for reliable job submission.
4. Worker locking and idempotent execution.
5. DynamoDB pagination and appropriate indexes.
6. Better retry and failure recovery strategies.
7. CloudWatch dashboards and DLQ alarms.
8. Integration testing and security testing.
